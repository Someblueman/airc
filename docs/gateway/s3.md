# Amazon S3 object mailbox

The selected object store is **Amazon S3 general-purpose buckets**, using the
regional HTTPS REST API and Signature Version 4. Each configured owner polls
one fixed prefix containing `request.jwe` and `result.jwe`. The request is an
encrypted, signed AIRC intent; the response is a whole signed/encrypted result.
Testing and deployment are deferred.

## Configuration and permissions

Add a top-level `s3` array with at most 16 owners:

```json
{
  "s3": [{
    "id": "alice-mailbox",
    "enabled": true,
    "region": "eu-west-2",
    "bucket": "example-airc-mailboxes",
    "account_id": "123456789012",
    "prefix": "alice/inbox",
    "credential_file": "/private/gateway/aws-s3.json",
    "route": {
      "principal": "alice",
      "target": {"kind": "room", "name": "#general"},
      "operations": ["send", "context.read", "history.read", "search"],
      "recipient_key_id": "alice-results",
      "recipient_public_key_file": "/private/gateway/alice-results.pem"
    }
  }]
}
```

Replace all resource and identity placeholders. The principal must already
grant the exact target and every selected operation, with a signing public key.
Configure the existing gateway request-decryption keys, Ed25519 response signer,
P-256 response recipient and, for history/search, cursor key. AWS credentials
use the same private JSON schema as [SQS](sqs.md): `access_key_id`,
`secret_access_key` and optional `session_token`. No ambient credential lookup
or automatic credential refresh occurs. Restart after rotating credentials.

This profile uses a commercial AWS region and a lowercase bucket name without
periods. The prefix is a canonical relative path of 1–256 ASCII bytes using
letters, digits, periods, underscores, hyphens and slashes; empty, dot and
dot-dot components and leading/trailing slashes are refused. Configured prefixes
cannot overlap within a bucket. The endpoint is fixed to
`https://<bucket>.s3.<region>.amazonaws.com`. Custom endpoints, redirects,
proxies, directory buckets, access points and alternate AWS partitions are
outside this profile. Every request includes the configured expected bucket
owner and uses system certificate trust.

Provision the bucket, producer account, IAM and any required KMS permissions
separately. Use an unversioned mailbox: the client refuses delete markers and
does not inspect or change the bucket's versioning configuration. Grant the
gateway object read/HEAD permissions for these two keys
and PutObject only for `result.jwe`. Give it the `s3:ListBucket` permission needed
to distinguish missing objects from denied access; the gateway makes no list
request. Restrict the producer to its mailbox. Gateway code does not inspect
IAM, set ACLs, create resources or delete any object. Account/region/ETag metadata
does not establish AIRC author identity. See the [S3 GetObject permission
contract](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html).

## Single-request mailbox

Run exactly one active gateway owner and one coordinated producer for a prefix.
This is a deployment precondition, not a distributed lease. The producer must
leave an outstanding request unchanged until its result has been consumed.

1. With both keys absent, create `request.jwe` using a conditional write and a
   whole compact JWE of at most 16 KiB. Set content type to `application/jose`
   or `application/octet-stream` without content encoding.
2. The gateway checks for `result.jwe` first. Any existing result blocks new
   processing and is preserved across restart.
3. It reads request metadata, retrieves the whole request with If-Match, and
   verifies the original signed principal, binding, target and allowed operation.
   Only Send, context, history and search are available; no streaming watches.
4. It rechecks request ETag and length, then creates the protected `result.jwe`
   with `If-None-Match: *`. It never overwrites an unread result.
5. The producer verifies the result's signature, recipient, scope, validity,
   request ciphertext digest and authenticated native request ID where present.
   Remove `request.jwe` first, then `result.jwe`, before submitting a new request.

S3's [conditional GET](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html)
and [conditional PUT](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html)
provide the object-level checks. ETags are opaque concurrency tokens; the
gateway hashes the complete request ciphertext separately for correlation.
An uncertain PUT outcome preserves the request; the next poll preserves any
published result. There is no temporary object or automatic cleanup. A stale,
malformed or mismatched result requires coordinated recovery with the gateway
stopped and the outstanding intent reconciled before removing it. Do not clear
objects while another publisher may still be active.

Original signed validity and native request identity govern admission. Redelivery
does not renew either. An expired encrypted Send can recover only an identical
retained journal result under current durable authorization; it cannot execute
again or admit a new job. Reads require fresh signed intent. Authentication and
operation errors produce a protected refusal for the fixed recipient, correlated
by request ciphertext digest. No failure changes or deletes the request object.
Whole-result capacity failures produce a protected capacity error.

## Protected result and ownership

`S3Result` contains version 1, protocol `aws/s3`, `request_sha256`, optional
authenticated `request_id`, target, and exactly one whole `result` or `error`.
The result uses the existing Ed25519 JWS inside P-256 ECDH-ES/A256GCM JWE
profile, with 32 KiB clear payload, 64 KiB token and 120-second lifetime limits.
Its response scope includes realm, principal and binding. The route is lowercase
SHA-256 hex of these values joined with NUL, without a trailing separator:

```text
airc-s3-response-v1, owner-id, region, bucket, account-id, prefix, target-kind, target-name
```

`S3ResponseScope` constructs this scope. Result publication confirms object
storage, not successful native AIRC delivery. Inspect the protected durable
Send state through the response and existing receipt mechanisms.

Each owner polls serially with a 15-second pass budget, one-second idle delay
and error backoff capped at 15 seconds. Native dispatch has three seconds.
Shared request capacity covers request retrieval, native work and publication.
Each HTTP client has at most two connections, 8 KiB response headers and bounded
whole bodies, with no application retry within a pass or HTTP redirect. Cancellation interrupts
requests; service shutdown joins owners before clearing AWS credentials and
response signing keys. Current object sizes and owner count are bounded;
version retention, lifecycle rules, cloud cost and old object versions remain
deployment responsibilities. No new dependency or durable schema is introduced.

A service readiness record confirms local preparation and owner startup; it
does not confirm AWS authentication or permissions. Requests sign the complete
payload hash and fixed conditional/owner headers according to [S3's SigV4
contract](https://docs.aws.amazon.com/AmazonS3/latest/developerguide/sig-v4-header-based-auth.html).

## Deferred verification

Production `go build ./...` passes for Darwin ARM64 and Linux AMD64/ARM64 with
`CGO_ENABLED=0`. Source review, formatting, whitespace and source-size advisory
checks pass. These checks do not establish runtime acceptance.

Real S3/IAM/KMS interoperability, expected-owner checks, conditional races,
uncertain publication, exact native author/target/body, encrypted whole reads,
replay, original expiry, capacity and joined shutdown remain untested. No AWS
resource or live AIRC service was contacted during implementation.
