# IEEE 802.15.4 through Linux 6LoWPAN

The selected bridge is a pair of Linux hosts with ATUSB IEEE 802.15.4 radios,
the kernel `atusb` driver, and an IPv6 `lowpan` interface over each `wpan`
interface. The existing framed TLS connector carries authenticated AIRC
requests and bounded replies over that radio path. This profile uses a direct
radio hop; it does not implement Zigbee or require a mesh-routing service.

The [Linux 802.15.4 guide](https://www.kernel.org/doc/html/latest/networking/ieee802154.html)
describes kernel 6LoWPAN support and the association between the two interfaces.
The [ATUSB driver configuration](https://github.com/torvalds/linux/blob/master/drivers/net/ieee802154/Kconfig)
identifies the concrete supported USB radio driver. Provision compatible radios,
firmware and kernel support on both hosts. Select the same permitted radio page,
channel and non-broadcast PAN ID, unique device addresses, compatible link
security policy, and an IPv6 subnet that does not overlap another interface.

Use `iwpan` from [wpan-tools](https://linux-wpan.org/wpan-tools.html) for radio
configuration and iproute2 for the `lowpan` interface. For an already configured
`wpan0`, the interface relationship is
`ip link add link wpan0 name lowpan0 type lowpan`. Bring up the radio and lowpan
interfaces, assign distinct IPv6 addresses and provision routes on both hosts.
These are operator network changes; the gateway neither runs these commands nor
loads drivers or changes radio settings. The
[Linux-WPAN setup reference](https://linux-wpan.org/documentation.html) describes
the default 1280-byte IPv6 MTU. Keep that adaptation-layer MTU; the much smaller
radio frame size is handled by kernel 6LoWPAN fragmentation and reassembly.

For example, after provisioning gateway `fd42:154::1/64` and peer
`fd42:154::2/64` on their actual lowpan interfaces, configure:

```json
{
  "id": "ieee802154",
  "protocol": "framed",
  "address": "[fd42:154::1]:7443",
  "enabled": true,
  "tls_cert_file": "/absolute/keys/gateway-chain.pem",
  "tls_key_file": "/absolute/keys/gateway-key.pem",
  "operations": ["send", "receipt.get", "context.read", "history.read", "search"]
}
```

Replace the illustrative subnet with the provisioned one. Configure existing
native bindings, principal signing keys, target grants and read cursor keys;
start `airc-gateway serve --file CONFIG`. The
[framed client](../../examples/gateway/framed-client/main.go) connects to the
numeric bracketed IPv6 address with a trusted CA, verified server name and ALPN
`airc-gateway/1`. TLS 1.3 and native signed/encrypted envelope checks remain
mandatory. Radio addresses, PAN membership and link keys confer no AIRC identity.

The [framed protocol](framed-stream-v1.md#wire-contract) retains whole-message
bounds, explicit read pages, deadlines, capacity controls and joined shutdown.
Fragment loss may prevent a request or reply from completing within the existing
deadline. Retain the original signed request identity for retries and distinguish
transport failure from native acceptance using receipts. Small messages/pages
are appropriate on this constrained path; no throughput claim is made.

No new gateway implementation is needed for this IPv6 carrier. Existing current
production builds passed for Darwin ARM64 and Linux AMD64/ARM64. The selected
radio profile is Linux-only. No radio setup, network command or runtime test
was executed. Deferred acceptance must use both real ATUSB radios and an
independent AIRC observer, establish that traffic crosses the lowpan/radio
interfaces, and cover exact author/target/body, complete bounded reads, TLS and
sender refusals, replay, fragmentation/loss, disconnects and shutdown. Simulator,
loopback, Wi-Fi and ordinary IPv6 evidence do not qualify the radio path.
